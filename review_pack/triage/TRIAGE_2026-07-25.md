## FORK #1 — Drive OAuth boots the user

ROOT CAUSE (three stacked defects, all in the callback path — the app session
itself was never touched; JWT lives in localStorage, TTL 86400s, stable
SECRET_KEY, verified surviving the round-trip):

1. `/v1/drive/connect` stored the OAuth `state` in a process-local dict.
   Auto-deploy restarts (every merge to main = new instance) emptied it
   mid-consent, so Google's redirect failed the state check.
2. Every callback failure raised a bare `400 {"detail": "Invalid or expired
   OAuth state."}` JSON page at `/v1/drive/callback` — the user was stranded
   OUTSIDE the SPA. That is the "booted / lost my session" experience.
3. Legacy Drive tokens written under the pre-credential-purge
   `DATA_ENCRYPTION_KEY` now raise DecryptionError (observed live 07:46:08Z,
   user 42565a93) — self-heals by clearing, but forces a reconnect through
   the fragile flow above.

FIX (branch `fix/triage-drive-oauth-callback`): stateless HMAC-signed state
(app signing secret; carries user_id + expiry + nonce + validated return_to;
survives restarts and any worker count), every callback failure path now 302s
back INTO the app with `?drive=error&reason=<slug>`, `return_to` lands the
user on the page they clicked Connect from, frontend shows a readable banner.
Open-redirect hardened (same-app absolute paths only). 58 drive tests green
incl. state-survives-restart, replay, tamper, expiry, exchange-failure.

Evidence (pre-fix, live prod): within-instance probe shows the machinery
working (`connect 200 → callback-denied 302 /?drive=error`) while
`callback-bogus → 400 raw JSON` — the stranding page. Render env verified:
FRONTEND_URL + GOOGLE_REDIRECT_URI both correct.

PARKED (needs operator): the final consent click needs the operator's Google
account (OAuth app is in testing mode — only listed test users can consent;
a pilot tester with an unlisted Google account gets Google's "access blocked"
403, which also reads as being booted — check the test-users list in Google
Cloud Console, or publish the consent screen).

## FORK #3 — "Answers from its ass" (ungrounded on empty/thin corpus)

NOT REPRODUCIBLE on current prod — the grounding gate behaves as designed:

- Brand-new EMPTY project, specific question ("design flow rate of the sewage
  pump station") → answer explicitly labeled "_This project has no documents
  of its own for this question — answering from the Master Corpus._" with a
  real citation (WWPS-01, 366 l/s, spec chunk #4658, score 0.75).
- Fabrication bait the corpus cannot answer (Riyadh Metro L7 contract value;
  Jeddah Marina mix strength) → honest "the provided context does not
  contain..." refusals, zero invented specifics, still labeled.
- After uploading one doc → same question class → grounded cited answer from
  the OWN doc (layer=own, score 0.867, "Project document" label).

Most probable original cause: during the Kimi-400 storm, synthesis fell back
(deterministic render / Groq scout) and produced boilerplate that read as
invention; fixed by #273–#275. Also noted out-of-scope: legacy non-stream
`/v1/chat` reports "offline mode" with a stale provider list (Groq/DeepSeek/
Ollama, pre-Kimi) — the UI uses `/v1/chat/stream` which is healthy, but that
endpoint's provider wiring was left behind by the Kimi-only ladder.

## CDEV #4 — "Generated chain failed validation" + doubled blueprint text

ROOT CAUSES (branch `fix/triage-factory-floor`):

(a) Validation failure = ROUTING leak, not a generator or validator defect.
    The exact error string exists only on the legacy kit-chain path. Two
    leaks sent a retail build there: (1) with a blueprint PENDING, any
    message that is not an approval/refinement/new-brief fell through to the
    legacy LLM chain generator, which invents block ids the registry
    correctly rejects — kernel refusal worked, routing did not; (2) the
    platform-intent regex missed standard phrasings ("I need a platform for
    retail", "want/give me/looking for/set up..."). Fixed: pending-blueprint
    fallthrough now stays in the platform flow with guidance, and the intent
    verbs are broadened. The validator is untouched — it correctly refuses
    invalid chains.

(b) Doubled text = double-emit protocol bug. The backend emitted the summary
    in the `blueprint`/`generation` card event AND re-streamed the same
    summary word-by-word as `delta` tokens; the frontend renders the card
    with the summary then appends deltas to the same bubble →
    "Blueprint drafted...Blueprint drafted...". Fixed: card events emit
    once, no delta re-stream (info replies, which have no card renderer,
    keep the delta stream). Bonus exposed+fixed: the generation bubble
    rendered the raw double-encoded JSON instead of its summary (frontend
    generation handler now parses like the blueprint handler).

Tests: 9 routing phrasings + kit-vocabulary negatives + SSE contract tests
(no legacy leak while pending; blueprint/generation emitted exactly once).
Factory suite 95/95 green.
